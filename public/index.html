Lesson 4 — PySpark DataFrames: select & filter ⚡

Reward: +300 XP · 🔓 Unlocks “PySpark pilot”

Why it matters: in Databricks, half your debugging is PySpark, not SQL. Good news — it's the same logic, new syntax. You already think in SELECT/WHERE; now you'll chain methods on a DataFrame instead.
🧠 Mental map: SELECT cols → df.select("a","b") · WHERE x > 25 → df.filter(F.col("x") > 25) · a DataFrame (df) is just a table held in a variable.
⚠️ The trap: PySpark is lazy — .select()/.filter() build a plan but show nothing until you call an action like .show() or .count().

▶ Databricks setup cell (Python — run this first)
from pyspark.sql import functions as F data = [(101, 1, 50), (102, 1, 30), (103, 2, 20)] df = spark.createDataFrame(data, ["order_id", "customer_id", "amount"]) df.show()

🎯 Task A — Translate SQL → PySpark

Reproduce SELECT order_id, amount FROM orders WHERE amount > 25 in PySpark, and call .show(). Predict first.

Chain the methods on df: .filter(F.col("amount") > 25) keeps the rows, .select("order_id","amount") picks the columns, .show() actually runs it. Order of filter/select doesn't matter here. .where(...) is an alias for .filter(...).
✔ Translation correct

🎯 Task B — Add a column with withColumn NEW

Add a fee column = 10% of amount using withColumn. Predict the fee on order 101.

df.withColumn("fee", F.col("amount") * 0.1) returns a NEW DataFrame with the extra column (it doesn't mutate df). F.col("amount") = "the amount column"; multiply it by 0.1 for 10%.
