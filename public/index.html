Lesson 3 — Window Functions: latest row per group 🪟

Reward: +250 XP · 🔓 Unlocks “Window wizard”

Why it matters: "give me the latest status per case", "the most recent balance per card", "keep one row per key (the newest)" — this is the daily bread of a Data Specialist. ROW_NUMBER() OVER (PARTITION BY … ORDER BY … DESC) numbers rows within each group; keep rn = 1 to grab the latest.
🧩 PARTITION BY = "restart the counter for each group." ORDER BY … DESC = "newest first, so rn 1 = latest."
⚠️ The trap: you cannot write WHERE rn = 1 in the same SELECT that creates rn — wrap it in a CTE/subquery first (or use Databricks QUALIFY).

▶ Databricks setup cell (run this first)
WITH case_status AS ( SELECT * FROM VALUES (10, 'open', DATE'2026-01-01'), (10, 'in_review', DATE'2026-01-03'), (10, 'closed', DATE'2026-01-05'), (20, 'open', DATE'2026-01-02'), (20, 'closed', DATE'2026-01-04') AS case_status(case_id, status, updated_at) ) SELECT * FROM case_status;

🎯 Task A — Rank rows within each case

Add a column rn = ROW_NUMBER() OVER (PARTITION BY case_id ORDER BY updated_at DESC). Predict before running.

The window function keeps ALL rows (5 of them) and just adds a number. PARTITION BY case_id restarts numbering per case. ORDER BY updated_at DESC → newest gets rn 1. So case 10's oldest row ('open', Jan 1) gets the highest rn.
✔ Ranking correct

🎯 Task B — Keep only the latest row per case THE TRAP

Return one row per case: its latest status. Wrap Task A in a CTE and filter rn = 1 (or use QUALIFY).

You can't filter a window function in the same WHERE. Two valid ways: (1) put the ROW_NUMBER query in a CTE WITH ranked AS (...) then SELECT ... FROM ranked WHERE rn = 1; or (2) Databricks shortcut: add QUALIFY ROW_NUMBER() OVER (...) = 1 directly.
✔ Latest-per-group correct
