Lesson 2 — Duplicate Detection 🕵️

Reward: +175 XP · 🔓 Unlocks “Dedup detective”

Why it matters: duplicate rows silently inflate your metrics — double-counted credit-card transactions pump up GMV, repeated scrape rows pump up OEU / new cases. A Data Specialist must detect and quantify dupes before trusting any table.
⚠️ The trap: SELECT DISTINCT only hides identical rows — it never tells you which key is duplicated or how many times. The real tool is GROUP BY … HAVING COUNT(*) > 1.

▶ Databricks setup cell (run this first)
WITH payments AS ( SELECT * FROM VALUES (1, 'AnaCard', 100), (2, 'BrunoCard', 50), (3, 'CarlaCard', 75), (2, 'BrunoCard', 50) -- ← duplicated transaction (txn 2 logged twice) AS payments(txn_id, card, amount) ) SELECT * FROM payments;

🎯 Task A — Detect the duplicate

Write a query that returns only the txn_id(s) that appear more than once, with how many times. Predict the answer before running.

Group rows by the key you suspect (txn_id), count rows per group with COUNT(*), then keep only groups bigger than 1 using HAVING COUNT(*) > 1. HAVING = a WHERE that runs after grouping.
✔ Duplicate detected

🎯 Task B — Quantify the GMV impact THE WHY

The dupe inflates GMV. Fill in all three (do the math from the setup data):

Naive = add all 4 rows. True = add the 3 distinct transactions (count txn 2 once). Inflation = Naive − True. Amounts: 100, 50, 75, and the duplicated 50.
